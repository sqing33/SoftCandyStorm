# 游戏愿景与设计支柱

## 一句话定位

《软糖风暴》是一款可爱糖果风的俯视角自动攻击肉鸽生存游戏，玩家在不断涌来的软糖怪潮中移动、躲避、升级甜点武器，修复失控的糖罐星。

## 核心玩家体验

玩家应该感受到三件事：

1. 画面很甜，但压力真的会越来越高。
2. 操作很简单，只需要移动和做升级选择。
3. 每局都会形成不同的甜点 Build，越打越热闹，越升级越夸张。

游戏不能只是“可爱皮肤的幸存者”。它需要通过糖果主题形成自己的记忆点：

- 敌人是软糖、果冻、棉花糖、布丁、焦糖机器。
- 武器是彩虹糖弹、棒棒糖回旋镖、汽水喷泉、棉花糖护盾。
- 经验是糖晶碎片。
- Boss 是暴走甜点机器或巨大糖果生物。
- 局内成长像“糖果魔法越来越失控”。

## 目标受众

主要玩家：

- 喜欢《吸血鬼幸存者》《Brotato》《20 Minutes Till Dawn》这类短局肉鸽的人。
- 喜欢可爱画风、轻松主题、但又想要一定挑战的玩家。
- 喜欢收集、解锁、组合武器和尝试流派的玩家。

次要玩家：

- 喜欢自动化、AI 生成内容、系统实验的人。
- 愿意体验不断更新内容包的玩家。

## 设计支柱

### 1. 可爱但不软弱

画风可以是圆润、明亮、甜美的，但游戏压力必须真实。敌人可以可爱，但数量、速度、组合和 Boss 机制要能制造紧张感。

表现方式：

- 低级小怪像软糖玩偶。
- 中后期怪潮像彩色洪水。
- Boss 外形可爱但压迫感强。
- 受伤反馈清楚，不做恐怖或血腥表现。

### 2. 一局十分钟，节奏完整

首个标准局长定为 10 分钟。每一局必须经历：

- 0:00-1:30 熟悉开局
- 1:30-3:30 第一轮压力和第一个 Build 分叉
- 3:30-5:00 第一个 Boss 检验
- 5:00-8:00 中期怪潮和流派成型
- 8:00-10:00 最终压力和风暴眼

后续可扩展 15 分钟、20 分钟模式，但 10 分钟模式是核心平衡单位。

### 3. Build 要有明显性格

每个流派应该玩起来不同，而不只是数值不同。

候选流派：

- 弹幕流：大量小糖弹，清小怪强。
- 环绕流：棒棒糖、棉花糖护盾，近身安全。
- 爆炸流：跳跳糖、汽水喷泉，间歇高爆发。
- 召唤流：布丁炮台、糖果小帮手，站位经营。
- 减速控制流：焦糖地面、薄荷冰霜，拖慢怪潮。
- 单体 Boss 流：焦糖光束、糖晶长枪，打 Boss 强。
- 经济流：糖晶吸附、经验增幅，前弱后强。

### 4. 内容可生成，但必须可约束

AI 可以生成大量内容，但不能直接进入正式游戏。每个内容都要被 Harness 校验：

- 是否格式合法
- 是否数值越界
- 是否与已有内容重复
- 是否造成性能爆炸
- 是否过强或过弱
- 是否破坏已有流派
- 是否有可读的主题和美术描述

### 5. Bot 是测试玩家，不是最终玩家

规则 Bot、Replay Bot、DQN/PPO Bot 用于发现问题：

- 是否过难
- 是否过简单
- 是否有无敌组合
- 是否有无解波次
- 是否有低性能怪潮
- 是否某个武器没人会选

但 Bot 不负责判断“爽不爽”。最终乐趣仍需要真人试玩。

## 差异化方向

### 主题差异化

糖果王国 + 软糖风暴，比传统暗黑、哥特、末日题材更轻，更适合广泛受众。

### 生产方式差异化

游戏内容通过 AI + Harness 生成、筛选、调平衡，形成“持续变甜的内容工厂”。

### 测试方式差异化

不是靠人工一局一局试，而是通过大量 bot、replay、headless simulation 建立内容质量门禁。

## 首个可发布 Demo 目标

Demo 不追求内容巨大，但必须完整：

- 1 个可玩角色
- 1 张地图
- 12 个武器
- 8 个被动
- 12 种普通敌人
- 3 个 Boss
- 10 分钟标准局
- 3-4 个明确流派
- 基础 meta 解锁
- 本地 replay 记录
- Harness 批量仿真报告

当前仓库提供纯 Python Demo readiness 审计器，把上述目标拆成正式内容数量、候选 full pack、Schema / 预算预检、历史 Bot / Replay、Runtime capture、原型素材、MetaProgress、人工试玩和 Release Candidate 状态：

```bash
python3 tools/validate_demo_readiness.py \
  --repo-root . \
  --allow-not-ready \
  --report harness/reports/2026-05-26_demo_readiness_current_local_001/demo_readiness.json \
  --markdown harness/reports/2026-05-26_demo_readiness_current_local_001/summary.md
```

当前结论为 `demo_not_ready`。正式 `content/base_demo` 已有 5 个角色、6 张地图、12 个武器、8 个被动、6 个 Boss、6 条 600 秒波次和 7 个 Build 标签组，但普通敌人仍为 8 个，低于 Demo 目标的 12 个。Phase 4 full pack 候选已补齐 12 个普通敌人和 12 个被动，并已通过 5 seed / 600 秒 all Bot 候选仿真和 45 条代表 Replay 回归进入 `simulated_candidates`；但它仍不能绕过人工试玩、final acceptance 和 accepted content lockfile。历史 Runtime capture、Bot 矩阵、Replay 回归和原型素材只证明已有链路，不代表当前可发布 Demo ready。

## 长期愿景

长期版本可以成为一个“自动扩展的可爱肉鸽”：

- 每周生成候选内容包
- Bot 自动跑平衡
- 人工挑选最有趣的内容
- 玩家获得新地图、新 Boss、新武器、新奇怪糖果事件
- 失败内容不会浪费，会进入修正队列继续迭代
