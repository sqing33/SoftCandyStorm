# 完整游戏流程与局外成长

## 核心定位

《软糖风暴》不是只有 10 分钟一局的独立小玩法。10 分钟是标准战斗单位，用于形成稳定节奏、方便平衡和 Harness 批量测试。

完整游戏流程应该是：

```text
局外准备
  -> 选择角色/地图/初始条件
  -> 10 分钟单局战斗
  -> 局后结算
  -> 解锁与章节推进
  -> 新内容进入下一局
```

玩家长期目标是修复糖罐星、探索糖果王国、解锁角色和武器进化、挑战更高风暴强度，而不是只打一局就结束。

## 玩家完整循环

### 1. 回到糖罐守护站

糖罐守护站是主菜单和局外基地。

功能：

- 选择角色
- 选择地图/章节
- 查看武器图鉴
- 查看敌人图鉴
- 查看糖罐星修复进度
- 查看已解锁进化配方
- 使用局外资源解锁新内容
- 进入下一次风暴巡逻

视觉上可以是一个小小糖果工坊：

- 中央是裂开的糖罐星模型。
- 左侧是角色和装备架。
- 右侧是图鉴和地图。
- 下方是开始巡逻按钮。

当前 Runtime 右侧局外面板已有五页文本视图：

- 五页顶部都显示 `F1` 到 `F5` 页签提示，并提供页签点击区，可在概览、章节、图鉴、设置和巡逻准备页之间切换；该入口复用现有 `base_ui_state.selected_panel` 写回路径。
- `F1`：糖罐守护站概览，显示资源、完成巡逻数、最佳时间、已解锁内容、最新结算，以及可选素材 Runtime 候选 manifest 的待预览状态；右下四段点击区也可跳转到章节、图鉴、设置和巡逻准备页。
- `F2`：章节目标，显示当前章节、地图、Boss、完成目标、锁定状态和本局变化；`Q/E` 和右下三段点击区可切换章节，`G` 或点击区第三段只会从已解锁章节启动巡逻，锁定章节不会被启动。
- `F3`：图鉴进度与条目浏览，显示各类图鉴发现数量、本局图鉴更新、`Q/E` 或手柄 `LT/RT` 分类切换、`B/N`、右下分段点击区或手柄十字键左 / 右条目切换、`V`、鼠标中键或手柄 `Y` 仅已发现 / 全部条目过滤，以及可选剧情 / 图鉴 UI 候选包的安全状态；未发现条目只显示锁定提示，不提前展示说明正文。
- `F4`：隐私与本地数据设置，显示上传型遥测、raw replay 上传和崩溃报告上传三个显式 opt-in 开关，并提供运行时存档 / 本地数据导出入口；`7/8/9/E/X/L/K` 键盘入口和右下七段点击区共用同一套 action，删除存档和删除本地数据需要再次触发同一删除 action 确认，切换面板或执行其他操作会取消确认态。
- `F5`：巡逻准备，显示当前角色、地图、初始装备、已解锁角色和已解锁地图；`C/M` 和右下两段点击区可循环已解锁角色 / 地图，切换后会重开当前巡逻并保留局外进度。

该面板默认只读取 `MetaProgress`、当前内容包中的已接受结构化内容和候选 manifest 元数据，不接入尚未真人审校的剧情 / 图鉴候选文本，也不加载尚未真人接受的候选图片或音频。Runtime 会把 F2 最近章节、F3 当前分类、仅已发现过滤和 F1-F5 最近面板选择写入 v1 存档的 `base_ui_state`，下次启动会恢复最近面板，未知面板值回退到 F1 概览；当前图鉴条目游标仍是会话内状态。启动时可显式传入 `--character-id <id>` 覆盖初始角色，Runtime 会从当前内容包读取该角色的初始装备；F2 面板的章节巡逻只允许已解锁章节，F5 面板内的角色 / 地图切换只循环 `MetaProgress` 中已解锁的条目。启动时可显式传入 `--story-codex-ui-candidate-manifest <path>`，Runtime 会读取已通过 `ui_candidate` manifest 的元数据，并在 F3 显示候选包 id、章节数、图鉴条目数和仍需验收状态。启动时也可显式传入 `--asset-runtime-candidate-manifest <path>`，Runtime 只读取 `asset-runtime-candidate-manifest-v0` 的批次 id、素材数量、类型统计、QA 状态、允许候选用途和候选池规则，并在 F1 显示 `asset_candidate` 待预览状态。两个入口都会拒绝越权 manifest：剧情 / 图鉴入口拒绝 `accepted_content=true`、`runtime_integrated=true` 或缺少 Runtime UI review / final human acceptance 要求的 manifest；素材入口还会拒绝 `release_ready=true` 或缺少 Runtime preview、音频响度审查、final human acceptance 要求的 manifest。因此它们不能绕过候选池红线；完整视觉基地 UI、完整可视化图鉴按钮布局、真实鼠标 / 手柄设备人工审查、已人工接受的剧情正文图鉴和正式素材接入仍待后续实现。

### 2. 选择巡逻目标

玩家选择一张地图或章节。

每张地图有：

- 推荐难度
- 已收集碎片数
- 主要敌人
- Boss
- 可解锁内容
- 风暴强度

例子：

```text
糖霜草地
- 推荐：新手
- Boss：暴走搅糖机
- 可解锁：棉花糖护盾、泡泡邮差
- 目标：找回第一片糖罐星碎片
```

### 3. 选择角色

角色决定开局手感和流派倾向。

角色提供：

- 初始武器
- 基础属性
- 独特被动
- 解锁目标
- 角色小剧情

角色不是永久强弱差异，而是不同玩法入口。

### 4. 进入单局

标准单局为 10 分钟。

一局内玩家只做两个核心决策：

- 怎么走位
- 升级时选什么

这种简单输入保证游戏适合大量内容和 Bot 测试。

### 5. 局内成长

局内成长包括：

- 获得新武器
- 升级武器
- 获得被动
- 触发进化
- 临时事件
- Boss 掉落

局内 Build 只在本局有效。

### 6. 局后结算

无论胜利或失败，都进入结算页。

结算内容：

- 存活时间
- 是否击败 Boss
- 击杀数
- 最终等级
- 本局 Build
- 武器伤害占比
- 主要死亡原因
- 获得糖晶碎片
- 新解锁
- 图鉴进度
- 是否保存 Replay

失败也给少量资源和图鉴进度，避免玩家感觉白玩。

## 10 分钟单局的意义

10 分钟不是内容上限，而是标准化容器。

它的作用：

1. 控制节奏，避免第一版过大。
2. 方便 Bot 批量跑成千上万局。
3. 方便比较不同版本和内容包。
4. 方便玩家碎片化游玩。
5. 作为标准模式的平衡基准。

后续可以扩展其他时长：

- 5 分钟挑战局
- 10 分钟标准局
- 15 分钟进阶局
- 20 分钟长局
- 无尽模式

但所有内容首先以 10 分钟标准局验证。

## 章节推进

主线章节：

```text
糖霜草地
  -> 汽水溪谷
  -> 棉花云牧场
  -> 焦糖工坊
  -> 果冻月台
  -> 裂星糖罐
```

每章包含：

- 1 张主地图
- 1-2 个普通 Boss
- 1 个章节 Boss
- 2-4 个新敌人
- 2-4 个新武器/被动
- 1 段剧情推进
- 1 个地图特色机制

### 解锁方式

章节解锁不建议只靠通关一次。推荐混合条件：

```text
击败本章 Boss
  + 收集足够糖罐星碎片
  + 完成 1 个章节目标
```

章节目标例子：

- 在糖霜草地存活 10 分钟。
- 击败暴走搅糖机。
- 使用彩虹糖弹达到 5 级。
- 收集 200 个糖晶。

这样即使玩家失败，也能逐步接近解锁。

## 局外资源

### 糖晶碎片

基础局外资源。

来源：

- 存活时间
- Boss 掉落
- 首次通关
- 图鉴收集
- 挑战任务

用途：

- 解锁角色
- 解锁武器进入掉落池
- 解锁被动进入掉落池
- 解锁地图信息
- 解锁图鉴条目

### 糖罐星碎片

主线推进资源。

来源：

- 首次击败章节 Boss
- 完成章节目标
- 特殊事件

用途：

- 修复糖罐星
- 解锁新章节
- 推进剧情

### 风暴糖粒

高阶挑战资源，后期加入。

来源：

- 高风暴强度通关
- 每日风暴
- 无尽模式

用途：

- 解锁外观
- 解锁高阶挑战
- 解锁特殊规则局

## 局外成长类型

### 内容解锁

最推荐作为主局外成长。

玩家解锁：

- 新角色
- 新武器
- 新被动
- 新进化配方
- 新地图
- 新事件

优点：

- 不破坏基础平衡太多。
- 玩家有新鲜感。
- 适合 AI 内容扩展。

### 轻量永久强化

可以有，但要克制。

例子：

- 初始可选武器 +1
- 开局糖晶 + 少量
- 图鉴提供轻微信息优势

不建议一开始做大量永久数值加成，否则 Harness 平衡会变复杂。

### 外观收集

安全且适合长期运营。

例子：

- 角色皮肤
- 糖罐帽子
- 武器特效颜色
- 糖晶拾取特效
- 守护站装饰

## 难度层级

### 普通风暴

主线标准难度。

目标：

- 新手可逐步通关。
- 中技能玩家有挑战。

### 强风暴

通关章节后解锁。

变化：

- 敌人更快
- 波次更密
- Boss 新阶段
- 奖励更多

### 奇味风暴

特殊规则难度。

例子：

- 敌人死亡后分裂更多
- 糖晶会慢慢消失
- 玩家拾取范围降低
- 所有武器冷却增加，但伤害提高

### 每日风暴

固定 seed 和规则。

用途：

- 玩家挑战排行榜，后续可选
- Harness 每日测试新内容
- 生成社区话题

## 游戏模式

### 标准巡逻

10 分钟主模式。

用途：

- 主线推进
- 解锁内容
- 平衡基准

### 长巡逻

15-20 分钟。

用途：

- 更完整 Build
- 更多进化
- 高阶玩家

### 无尽风暴

没有固定结束，怪潮不断增强。

用途：

- 测极限 Build
- 后期挑战
- Harness 性能压力测试

### 章节挑战

固定角色、固定初始武器、固定地图规则。

用途：

- 教玩家流派
- 解锁特殊内容
- 测试特定机制

### 实验风暴

由 AI 生成候选内容组成的测试模式。

注意：

- 不进入主线。
- 标记为实验内容。
- 可用于内部测试或未来公开 beta。

## 图鉴系统

图鉴是轻量长期目标。

分类：

- 软糖怪图鉴
- Boss 图鉴
- 武器图鉴
- 被动图鉴
- 进化图鉴
- 地图图鉴
- 风暴事件图鉴

图鉴内容：

- 名称
- 可爱描述
- 行为提示
- 首次发现时间
- 击败次数
- 掉落或解锁关联

图鉴可以为玩家提供信息，但不必给强数值奖励。

当前剧情 / 图鉴候选包位于：

```text
harness/generated_candidates/2026-05-26_story_codex_seed_pack/
```

该候选包已通过结构、引用和基础文案护栏校验，并新增人工审校草稿：

```text
harness/story_review/drafts/2026-05-26_story_codex_seed_pack_review_draft.json
```

草稿覆盖 6 个章节剧情片段和 26 条图鉴文本，但仍包含 `TODO` 占位，默认结论为 `needs_more_review`。它只用于后续真人审校防漏项；在真人填写并通过 `harness/story_review/validate_story_codex_manual_review.py` 前，不得进入 Runtime 图鉴 UI 候选或正式内容池。若真人审校结论为 `ui_candidate`，可以用 `harness/story_review/promote_story_codex_ui_candidate.py` 复制到 `harness/story_review/ui_candidates/`，但该目录仍只是 UI 接入候选，不等于 `accepted_content` 或 Runtime 集成。UI 候选 manifest 必须继续通过 `harness/story_review/validate_story_codex_ui_candidate_manifest.py`，确认人工审校绑定、章节 / 图鉴计数和“不进入正式内容池 / 不标记 Runtime 集成”的规则。

Runtime 当前可用 `--story-codex-ui-candidate-manifest <path>` 读取 UI 候选 manifest 的安全元数据，并在 F3 图鉴页显示候选包 id、章节数、图鉴条目数和待验收状态。F3 同时提供基于当前内容包与 `MetaProgress` 的图鉴条目浏览：`Q/E` 或手柄 `LT/RT` 切换角色、武器、被动、敌人、Boss、地图、进化和事件分类，`B/N`、右下分段点击区或手柄十字键左 / 右切换条目，`V`、鼠标中键或手柄 `Y` 切换仅已发现 / 全部条目；未发现条目只显示锁定提示，不提前展示说明文本。右下分段点击区按从左到右五段映射为上一类、下一类、上一条、下一条和过滤切换；该入口只接受 `story-codex-ui-candidate-manifest-v0`、`stage=story_codex_ui_candidate`、`manual_gate_decision=ui_candidate`，并要求 `accepted_content=false`、`runtime_integrated=false`、`requires_runtime_ui_review=true`、`requires_final_human_acceptance=true`。它不会读取候选章节或图鉴正文，也不代表剧情已经进入正式 Runtime UI。

剧情 / 图鉴最终接受还需要额外的 acceptance manifest 门禁。`harness/story_review/create_story_codex_acceptance_review_packet.py` 会先把 UI 候选 manifest、Runtime UI review、final human acceptance 和 manifest 顶层占位状态汇总成最终接受审查包，帮助真人补齐证据；它不校验最终接受通过、不复制正文、不接入 Runtime，也不批准发布。`harness/story_review/validate_story_codex_runtime_ui_review.py` 独立校验 Runtime UI review 记录，要求 F3 入口可见、没有加载 generated candidate 正文、没有 Runtime 集成声明、布局可读并有至少两条具体观察。`harness/story_review/validate_story_codex_final_acceptance.py` 独立校验 final human acceptance 记录，要求它绑定 `runtime_ui_review_pass` 且不能声明 Runtime 集成或发布 ready。`harness/story_review/validate_story_codex_acceptance_manifest.py` 再汇总三段证据，要求绑定有效 UI 候选 manifest、已通过 Runtime UI review 记录和已通过 final human acceptance 记录，并要求 `accepted_content=true`、`runtime_integrated=false`、`release_ready=false`、`generated_candidate_direct_acceptance_allowed=false`。因此它可以记录“文本已被人工接受”，但不能代表 Runtime 已集成、发布包 ready，也不能让 generated candidate 绕过审校和 UI 候选链路。

素材 Runtime 候选可用 `--asset-runtime-candidate-manifest <path>` 读取 manifest 的安全元数据，并在 F1 概览页显示候选批次、素材数量、类型统计和 `asset_candidate` 待预览状态。该入口只接受 `asset-runtime-candidate-manifest-v0`、`stage=asset_runtime_candidate`、`manual_gate_decision=asset_candidate`，并要求 `accepted_content=false`、`runtime_integrated=false`、`release_ready=false`、`requires_runtime_preview=true`、`requires_audio_loudness_review=true`、`requires_final_human_acceptance=true`。它不会读取候选图片或音频文件，不替换正式 Runtime 素材，也不代表素材已通过人工接受。

## 存档契约

局外成长需要可保存、可导出、可删除的本地存档。存档模板位于：

```text
harness/save_contract/save_state_v0_template.json
harness/save_contract/save_state_v1_template.json
harness/save_contract/platform_save_path_policy_v0.json
```

存档至少覆盖：

- `schema_version`、`save_id`、`profile_id`、`game_version`、`ruleset_version`
- 当前启用内容包 `content_pack_ids`
- 上传型遥测、raw replay 上传和崩溃报告上传默认关闭的 `settings`
- 删除存档、导出存档、保留天数和 opt-in 上传要求的 `data_controls`
- 局外资源 `candy_crystal_shards`、`star_shards`、`storm_grains`
- 已解锁角色、武器、被动、地图、进化、章节、事件和外观
- 角色、武器、被动、敌人、Boss、地图、进化和事件图鉴进度
- 章节解锁状态和已完成目标
- 已完成局数和最佳存活时间

当前校验入口：

## 首个 Demo 的完整流程

Demo 不需要做全部章节，但需要一个完整闭环。

建议 Demo：

- 1 个守护站界面
- 2 个角色
- 1 张地图：糖霜草地
- 1 个 10 分钟标准巡逻

```text
我打完一局后，还有新东西想解锁；
```
