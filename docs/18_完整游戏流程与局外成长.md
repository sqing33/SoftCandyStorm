# 完整游戏流程与局外成长

## 核心定位

《软糖风暴》不是只有 10 分钟一局的独立小玩法。10 分钟是标准战斗单位，用于形成稳定节奏、方便平衡和 Harness 批量测试。

完整游戏流程应该是：

```text
局外准备
  -> 选择角色/地图/初始条件
  -> 10 分钟单局战斗
  -> 局后结算
  -> 解锁与章节推进
  -> 新内容进入下一局
```

玩家长期目标是修复糖罐星、探索糖果王国、解锁角色和武器进化、挑战更高风暴强度，而不是只打一局就结束。

## 玩家完整循环

### 1. 回到糖罐守护站

糖罐守护站是主菜单和局外基地。

功能：

- 选择角色
- 选择地图/章节
- 查看武器图鉴
- 查看敌人图鉴
- 查看糖罐星修复进度
- 查看已解锁进化配方
- 使用局外资源解锁新内容
- 进入下一次风暴巡逻

视觉上可以是一个小小糖果工坊：

- 中央是裂开的糖罐星模型。
- 左侧是角色和装备架。
- 右侧是图鉴和地图。
- 下方是开始巡逻按钮。

当前 Runtime 右侧局外面板已有三页文本视图：

- `F1`：糖罐守护站概览，显示资源、完成巡逻数、最佳时间、已解锁内容和最新结算。
- `F2`：章节目标，显示已解锁章节、地图、Boss 和完成目标。
- `F3`：图鉴进度，显示各类图鉴发现数量和本局图鉴更新。
- `F4`：隐私与本地数据设置，显示上传型遥测、raw replay 上传和崩溃报告上传三个显式 opt-in 开关。

该面板只读取 `MetaProgress`，不接入尚未真人审校的剧情 / 图鉴候选文本；完整基地 UI、角色/地图选择界面和可点击图鉴仍待后续实现。

### 2. 选择巡逻目标

玩家选择一张地图或章节。

每张地图有：

- 推荐难度
- 已收集碎片数
- 主要敌人
- Boss
- 可解锁内容
- 风暴强度

例子：

```text
糖霜草地
- 推荐：新手
- Boss：暴走搅糖机
- 可解锁：棉花糖护盾、泡泡邮差
- 目标：找回第一片糖罐星碎片
```

### 3. 选择角色

角色决定开局手感和流派倾向。

角色提供：

- 初始武器
- 基础属性
- 独特被动
- 解锁目标
- 角色小剧情

角色不是永久强弱差异，而是不同玩法入口。

### 4. 进入单局

标准单局为 10 分钟。

一局内玩家只做两个核心决策：

- 怎么走位
- 升级时选什么

这种简单输入保证游戏适合大量内容和 Bot 测试。

### 5. 局内成长

局内成长包括：

- 获得新武器
- 升级武器
- 获得被动
- 触发进化
- 临时事件
- Boss 掉落

局内 Build 只在本局有效。

### 6. 局后结算

无论胜利或失败，都进入结算页。

结算内容：

- 存活时间
- 是否击败 Boss
- 击杀数
- 最终等级
- 本局 Build
- 武器伤害占比
- 主要死亡原因
- 获得糖晶碎片
- 新解锁
- 图鉴进度
- 是否保存 Replay

失败也给少量资源和图鉴进度，避免玩家感觉白玩。

## 10 分钟单局的意义

10 分钟不是内容上限，而是标准化容器。

它的作用：

1. 控制节奏，避免第一版过大。
2. 方便 Bot 批量跑成千上万局。
3. 方便比较不同版本和内容包。
4. 方便玩家碎片化游玩。
5. 作为标准模式的平衡基准。

后续可以扩展其他时长：

- 5 分钟挑战局
- 10 分钟标准局
- 15 分钟进阶局
- 20 分钟长局
- 无尽模式

但所有内容首先以 10 分钟标准局验证。

## 章节推进

主线章节：

```text
糖霜草地
  -> 汽水溪谷
  -> 棉花云牧场
  -> 焦糖工坊
  -> 果冻月台
  -> 裂星糖罐
```

每章包含：

- 1 张主地图
- 1-2 个普通 Boss
- 1 个章节 Boss
- 2-4 个新敌人
- 2-4 个新武器/被动
- 1 段剧情推进
- 1 个地图特色机制

### 解锁方式

章节解锁不建议只靠通关一次。推荐混合条件：

```text
击败本章 Boss
  + 收集足够糖罐星碎片
  + 完成 1 个章节目标
```

章节目标例子：

- 在糖霜草地存活 10 分钟。
- 击败暴走搅糖机。
- 使用彩虹糖弹达到 5 级。
- 收集 200 个糖晶。

这样即使玩家失败，也能逐步接近解锁。

## 局外资源

### 糖晶碎片

基础局外资源。

来源：

- 存活时间
- Boss 掉落
- 首次通关
- 图鉴收集
- 挑战任务

用途：

- 解锁角色
- 解锁武器进入掉落池
- 解锁被动进入掉落池
- 解锁地图信息
- 解锁图鉴条目

### 糖罐星碎片

主线推进资源。

来源：

- 首次击败章节 Boss
- 完成章节目标
- 特殊事件

用途：

- 修复糖罐星
- 解锁新章节
- 推进剧情

### 风暴糖粒

高阶挑战资源，后期加入。

来源：

- 高风暴强度通关
- 每日风暴
- 无尽模式

用途：

- 解锁外观
- 解锁高阶挑战
- 解锁特殊规则局

## 局外成长类型

### 内容解锁

最推荐作为主局外成长。

玩家解锁：

- 新角色
- 新武器
- 新被动
- 新进化配方
- 新地图
- 新事件

优点：

- 不破坏基础平衡太多。
- 玩家有新鲜感。
- 适合 AI 内容扩展。

### 轻量永久强化

可以有，但要克制。

例子：

- 初始可选武器 +1
- 开局糖晶 + 少量
- 图鉴提供轻微信息优势

不建议一开始做大量永久数值加成，否则 Harness 平衡会变复杂。

### 外观收集

安全且适合长期运营。

例子：

- 角色皮肤
- 糖罐帽子
- 武器特效颜色
- 糖晶拾取特效
- 守护站装饰

## 难度层级

### 普通风暴

主线标准难度。

目标：

- 新手可逐步通关。
- 中技能玩家有挑战。

### 强风暴

通关章节后解锁。

变化：

- 敌人更快
- 波次更密
- Boss 新阶段
- 奖励更多

### 奇味风暴

特殊规则难度。

例子：

- 敌人死亡后分裂更多
- 糖晶会慢慢消失
- 玩家拾取范围降低
- 所有武器冷却增加，但伤害提高

### 每日风暴

固定 seed 和规则。

用途：

- 玩家挑战排行榜，后续可选
- Harness 每日测试新内容
- 生成社区话题

## 游戏模式

### 标准巡逻

10 分钟主模式。

用途：

- 主线推进
- 解锁内容
- 平衡基准

### 长巡逻

15-20 分钟。

用途：

- 更完整 Build
- 更多进化
- 高阶玩家

### 无尽风暴

没有固定结束，怪潮不断增强。

用途：

- 测极限 Build
- 后期挑战
- Harness 性能压力测试

### 章节挑战

固定角色、固定初始武器、固定地图规则。

用途：

- 教玩家流派
- 解锁特殊内容
- 测试特定机制

### 实验风暴

由 AI 生成候选内容组成的测试模式。

注意：

- 不进入主线。
- 标记为实验内容。
- 可用于内部测试或未来公开 beta。

## 图鉴系统

图鉴是轻量长期目标。

分类：

- 软糖怪图鉴
- Boss 图鉴
- 武器图鉴
- 被动图鉴
- 进化图鉴
- 地图图鉴
- 风暴事件图鉴

图鉴内容：

- 名称
- 可爱描述
- 行为提示
- 首次发现时间
- 击败次数
- 掉落或解锁关联

图鉴可以为玩家提供信息，但不必给强数值奖励。

当前剧情 / 图鉴候选包位于：

```text
harness/generated_candidates/2026-05-26_story_codex_seed_pack/
```

该候选包已通过结构、引用和基础文案护栏校验，并新增人工审校草稿：

```text
harness/story_review/drafts/2026-05-26_story_codex_seed_pack_review_draft.json
```

草稿覆盖 6 个章节剧情片段和 26 条图鉴文本，但仍包含 `TODO` 占位，默认结论为 `needs_more_review`。它只用于后续真人审校防漏项；在真人填写并通过 `harness/story_review/validate_story_codex_manual_review.py` 前，不得进入 Runtime 图鉴 UI 候选或正式内容池。若真人审校结论为 `ui_candidate`，可以用 `harness/story_review/promote_story_codex_ui_candidate.py` 复制到 `harness/story_review/ui_candidates/`，但该目录仍只是 UI 接入候选，不等于 `accepted_content` 或 Runtime 集成。

## 存档契约

局外成长需要可保存、可导出、可删除的本地存档。v0 存档模板位于：

```text
harness/save_contract/save_state_v0_template.json
```

存档至少覆盖：

- `schema_version`、`save_id`、`profile_id`、`game_version`、`ruleset_version`
- 当前启用内容包 `content_pack_ids`
- 上传型遥测、raw replay 上传和崩溃报告上传默认关闭的 `settings`
- 删除存档、导出存档、保留天数和 opt-in 上传要求的 `data_controls`
- 局外资源 `candy_crystal_shards`、`star_shards`、`storm_grains`
- 已解锁角色、武器、被动、地图、进化、章节、事件和外观
- 角色、武器、被动、敌人、Boss、地图、进化和事件图鉴进度
- 章节解锁状态和已完成目标
- 已完成局数和最佳存活时间

当前校验入口：

```bash
python3 tools/validate_save_state_contract.py \
  harness/save_contract/save_state_v0_template.json \
  --report harness/reports/2026-05-26_save_state_contract_001/save_state_contract.json \
  --markdown harness/reports/2026-05-26_save_state_contract_001/summary.md
```

报告结论为 `save_state_contract_valid`。这只证明 JSON 存档形状、图鉴/章节字段和本地数据控制项完整；Runtime 真实读写、存档迁移、UI 删除/导出按钮和平台存档位置仍需要后续实现与人工验证。

Runtime 现在已有 v0 本地存档读写入口：

```bash
cargo run -p game_runtime -- --save-file harness/save/local/profile.json
cargo run -p game_runtime -- --save-file harness/save/local/profile.json --export-save harness/save/local/profile_export.json
cargo run -p game_runtime -- --save-file harness/save/local/profile.json --delete-save
```

`--save-file` 启动时会读取 `save-state-v0`；文件不存在时会创建 demo 初始存档。初始存档已经包含糖霜草地到裂星糖罐的六章主线骨架，只有糖霜草地默认解锁；击败糖霜草地 Boss 并获得足够星片后，GameCore 会同时解锁 `soda-creek` 地图和章节进度。单局结算后，Runtime 会把 `MetaProgress` 写回该存档。`--export-save` 会导出同形状 JSON 副本；`--delete-save` 必须显式传入 `--save-file`，只删除指定文件。该能力仍未完成迁移版本、基地 UI、平台云存档或人工验证。

Runtime 隐私设置页还需要遵守可校验契约：

```text
harness/telemetry_privacy/runtime_privacy_settings_contract_v0.json
harness/reports/2026-05-26_runtime_privacy_settings_contract_001/summary.md
```

该契约要求局外设置页提供上传型遥测、raw replay 上传和崩溃报告上传三个默认关闭的开关，并提供删除本地数据、导出本地数据和隐私说明入口。报告结论为 `runtime_privacy_settings_contract_valid`；Runtime 已有 `F4` 键盘设置页和 JSON 持久化，但删除 / 导出仍是 CLI 入口，平台存档路径、发布级 UI 验证和人工隐私审查仍待完成。

Runtime 现在已有首个本地数据控制实现：

```bash
cargo run -p game_runtime -- --print-privacy-notice
cargo run -p game_runtime -- --runtime-settings-file harness/telemetry/local/runtime_settings.json --export-local-data harness/telemetry/local/export.json
cargo run -p game_runtime -- --local-data-dir harness/telemetry/local/manual-smoke --delete-local-data
```

该实现用于补齐局外设置页背后的本地能力：隐私设置默认全关、试玩 capture 报告写入隐私摘要、本地遥测 / replay 可导出 JSON、显式指定目录后可删除本地数据。Runtime 现在也提供 `F4` 设置页，可用 `7/8/9` 切换三个上传同意项；如果启动时传入 `--runtime-settings-file`，切换结果会写回 JSON，否则只在当前会话生效。它仍不是完整基地 UI、正式存档迁移、平台存档位置、发布级导出 / 删除按钮验证或隐私法律审查。

## 主线完成后的循环

主线通关后，不应结束。

后续目标：

- 解锁全部角色
- 完成全部进化
- 挑战强风暴
- 挑战每日风暴
- 收集外观
- 打无尽模式
- 尝试 AI 生成的新内容包

## 与 Harness 的关系

完整游戏流程也要被 Harness 覆盖。

Harness 不只测一局，还要测：

- 解锁是否可达
- 玩家是否过早解锁高阶内容
- 某张地图是否资源过多
- 某个章节是否卡进度
- 每日风暴是否无解
- 长局模式是否性能失控
- 无尽模式是否出现实体爆炸

Bot 和 Replay 对应：

- 标准巡逻：主要平衡测试
- 长巡逻：Build 深度测试
- 无尽风暴：性能和极限测试
- 章节挑战：机制专项测试
- 每日风暴：固定 seed 对比

## 首个 Demo 的完整流程

Demo 不需要做全部章节，但需要一个完整闭环。

建议 Demo：

- 1 个守护站界面
- 2 个角色
- 1 张地图：糖霜草地
- 1 个 10 分钟标准巡逻
- 1 个章节 Boss：暴走搅糖机
- 8-12 个武器/被动
- 2-3 个进化
- 简单图鉴
- 简单解锁
- 局后结算

Demo 的目标是让玩家觉得：

```text
我打完一局后，还有新东西想解锁；
我换一个角色或武器，下一局会不一样；
这个世界还有后续地图。
```
