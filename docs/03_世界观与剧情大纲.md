# 世界观与剧情大纲

## 世界概念

软糖王国是一片由糖晶矿、果冻河、棉花云、汽水泉和焦糖工坊组成的小小世界。这里没有传统太阳，天空中挂着许多发光的糖罐星。

每颗糖罐星都储存着居民一天的快乐。糖罐星越亮，王国越稳定；糖罐星越暗，王国就会变得黏糊、混乱、失去方向。

## 风暴起因

很久以来，软糖王国有一个传统：

> 不开心的味道要藏起来，甜甜的笑容要挂到天上。

居民把酸、苦、辣、咸等情绪都封进糖罐星深处，只留下甜味照亮世界。久而久之，最大的糖罐星承受了太多被藏起来的味道，某天夜里突然裂开。

裂开的糖罐星把魔法糖浆洒向天空，形成了无法停止的软糖风暴。

风暴雨点落到地面后会变成各种软糖怪。它们不是邪恶生物，而是被压抑的情绪和甜味混在一起，变得过度兴奋、黏人、混乱。

## 主角设定

玩家扮演新上任的糖罐守护员。

### 主角身份

主角原本只是见习守护员，日常工作包括：

- 擦亮糖罐星
- 给布丁花浇汽水
- 记录每天有多少颗星星变甜
- 修补被风吹歪的棒棒糖路标

风暴爆发时，老守护员们都被黏在巨型太妃糖里，只有主角因为正在仓库找拖把而躲过一劫。

### 主角性格

- 有点慌，但很认真。
- 不擅长打架，但很会使用各种甜点工具。
- 相信怪物不是坏东西，只是需要被“重新装回糖罐”。

### 玩法解释

主角不主动攻击，因为守护员的职责不是伤害别人，而是启动自动防护糖具：

- 彩虹糖弹会自动弹出。
- 棉花糖护盾会围着主角转。
- 布丁炮台会自己瞄准。
- 汽水喷泉会在危险处喷发。

## 核心主题

故事主题：

> 不是所有情绪都要变甜，世界需要各种味道。

游戏早期看起来是“打败软糖怪、修复糖罐星”，但后期逐渐揭示：风暴不是外敌，而是王国长期只追求甜味的后果。

最终主角不是消灭风暴，而是学会调和不同味道，让糖罐星从单一粉色变成彩虹色。

## 章节大纲

### 第一章：糖霜草地

新手区域。草地上覆盖糖霜，最常见的是蹦蹦软糖。

剧情目标：

- 主角发现风暴雨点会变成软糖怪。
- 找到第一片糖罐星碎片。
- 遇见第一位被困居民。

Boss：暴走搅糖机。

主题：混乱刚刚开始。

### 第二章：汽水溪谷

汽水泉喷涌失控，地面到处是泡泡和弹跳水流。

敌人更多具有冲刺、爆开、分裂特性。

剧情目标：

- 主角发现软糖怪不是从外面来的，而是糖罐星碎片变出来的。
- 学会利用酸味和气泡的力量。

Boss：汽水喷泉龙。

主题：被压住的情绪开始冒泡。

### 第三章：棉花云牧场

漂浮云朵和棉花糖团组成的区域，视觉柔软但移动空间会不断变化。

剧情目标：

- 主角遇到老守护员留下的记录。
- 记录暗示王国一直把“不够甜”的情绪藏起来。

Boss：巨型棉花团。

主题：温柔也可能让人窒息。

### 第四章：焦糖工坊

工坊原本负责把糖浆做成糖罐星外壳，现在机器全部过热。

敌人具有高血量、黏地、减速和范围伤害。

剧情目标：

- 主角发现糖罐星被设计成只允许甜味外溢。
- 焦糖工坊是压抑情绪的核心设施。

Boss：焦糖熔炉。

主题：越压越黏，越藏越重。

### 第五章：果冻月台

连接各地的果冻列车停摆，风暴怪从不同方向涌来。

地图机制更强，适合做多路线、生存压力和移动挑战。

剧情目标：

- 主角收集足够碎片，准备进入天空裂口。
- 居民开始理解软糖怪并非敌人。

Boss：巨型熊糖王。

主题：面对被误解的情绪。

### 最终章：裂星糖罐

主角进入破裂的最大糖罐星内部。这里不再是普通地图，而是彩色风暴核心。

最终 Boss：裂星糖罐核心。

战斗阶段：

1. 甜味洪流
2. 酸味气泡
3. 苦味黑糖
4. 辣味流星
5. 彩虹调和

结局：

- 主角把所有味道重新放回天空。
- 糖罐星不再单纯发粉色光，而是变成彩虹色。
- 一部分软糖怪恢复成居民，一部分成为伙伴，一部分进入图鉴。

## 主要角色

### 糖罐守护员

玩家角色。见习守护员，风暴后被迫承担拯救任务。

### 老守护员奶糖伯

前任守护员，被黏在太妃糖里。通过记录和短对话给玩家提示。

### 泡泡邮差

负责在章节间传递消息，会带来新解锁和轻量剧情。

### 酸梅博士

研究非甜味情绪的学者。早期被当成怪人，后期证明他的理论正确。

### 糖罐星核心

最终对话对象，不是纯反派。它因为承受太多被隐藏的情绪而崩溃。

## 剧情呈现方式

不建议做大量长文本。适合：

- 局前 2-3 句短对话
- Boss 出场一句话
- 解锁新区域时一段短叙述
- 图鉴里补世界观
- 章节完成后 30 秒以内的小剧情

## 剧情与图鉴候选实现状态

当前已有一批剧情 / 图鉴候选内容，位置：

```text
harness/generated_candidates/2026-05-26_story_codex_seed_pack/
```

该候选包覆盖：

- 6 个章节剧情片段：每章包含 `unlock_summary`、局前短句、Boss 出场一句话、章节完成总结和图鉴解锁列表。
- 26 条图鉴文本：覆盖世界观、5 个角色、6 个普通敌人、6 个 Boss 和 6 张地图。

该批内容仍属于 `generated_candidates`，不是正式剧情内容，也不能直接进入 `accepted_content`。Runtime 只允许读取已通过 `ui_candidate` manifest 的安全元数据，用于显示候选包状态，不允许读取或展示候选正文。进入后续阶段前至少需要：

- 运行 `tools/validate_story_codex_candidates.py` 完成结构、引用、候选池红线和基础文案护栏检查。
- 由人工审校剧情语气、剧透节奏、角色一致性和 UI 文案长度。
- 如果人工审校结论为 `ui_candidate`，运行 `harness/story_review/promote_story_codex_ui_candidate.py` 进入 `harness/story_review/ui_candidates/`。
- 未来建立 story/codex UI 后，必须先完成 Runtime UI review 和最终人工接受，再用 `harness/story_review/validate_story_codex_acceptance_manifest.py` 校验最终接受 manifest；该 manifest 不代表 Runtime 已集成或 release ready。

人工审校记录模板、草稿生成器与校验器位于：

```text
harness/story_review/story_codex_manual_review_template.json
harness/story_review/create_story_codex_review_draft.py
harness/story_review/create_story_codex_review_packet.py
harness/story_review/validate_story_codex_manual_review.py
harness/story_review/promote_story_codex_ui_candidate.py
harness/story_review/validate_story_codex_ui_candidate_manifest.py
harness/story_review/validate_story_codex_acceptance_manifest.py
harness/story_review/story_codex_ui_candidate_manifest_template.json
harness/story_review/story_codex_acceptance_manifest_template.json
harness/story_review/drafts/2026-05-26_story_codex_seed_pack_review_draft.json
harness/reports/2026-05-26_story_codex_review_packet_001/summary.md
```

草稿生成器会为候选包内全部章节和图鉴条目生成 `TODO` 占位审校记录，默认 `gate_decision` 为 `needs_more_review`。审校包生成器会把 6 个章节、26 条图鉴、候选校验报告和草稿状态汇总成 Markdown，方便真人逐项审校；它不判断文案质量、不填写评分、不推进候选。UI 候选晋级工具只接受已通过校验且 `gate_decision=ui_candidate` 的人工审校记录，且不会写入 `accepted_content` 或接入 Runtime。UI 候选 manifest 还需要通过 `validate_story_codex_ui_candidate_manifest.py`，确认候选仍绑定人工审校、计数匹配、不标记 Runtime 集成，也不声明 Release ready。

最终接受 manifest 只允许在 UI 候选 manifest 已有效、Runtime UI review 已通过、final human acceptance 已填写且通过后成立。它要求 `accepted_content=true`，但同时要求 `runtime_integrated=false`、`release_ready=false` 和 `generated_candidate_direct_acceptance_allowed=false`，用于防止从 `generated_candidates` 直接进入正式剧情 / 图鉴内容或把文案接受误读为 Runtime 集成。

Runtime 当前提供安全状态入口：

```bash
cargo run -p game_runtime -- \
  --story-codex-ui-candidate-manifest harness/story_review/ui_candidates/<candidate>/ui_candidate_manifest.json
```

该入口只解析 `story-codex-ui-candidate-manifest-v0` 中的 `candidate_pack_id`、章节数、图鉴条目数、`manual_gate_decision=ui_candidate` 和候选池规则；若 manifest 声明 `accepted_content=true`、`runtime_integrated=true`，或缺少 `requires_runtime_ui_review` / `requires_final_human_acceptance`，Runtime 会拒绝加载。F3 图鉴页只显示“剧情/图鉴 UI 候选待验收”的状态，不读取 `generated_candidates` 正文、不展示未最终接受的剧情句子，也不代表 Runtime UI review 或最终人工接受已经完成。

## 文案语气

可爱，但不要过度幼稚。

例子：

- “风暴又变甜了，也变得更黏了。”
- “别担心，它们只是太想被看见。”
- “糖罐星不是坏掉了，它只是装不下了。”
- “今天的天空，有一点酸，但很好看。”
