# 阶段路线图

## Phase 0：文档与方向锁定

目标：

- 确定游戏名《软糖风暴》。
- 确定可爱糖果风。
- 确定 Bevy + Harness + Python RL 方向。
- 建立完整设计文档。

交付：

- docs/
- 世界观
- 核心玩法规格
- Bot 计划
- Harness 计划
- AI 内容生成计划

当前文档即 Phase 0 交付。

## Phase 1：Bevy GameCore 原型

目标：

- 不做正式美术。
- 不做完整 UI。
- 先做 headless 可跑的 GameCore。

内容：

- Bevy workspace
- game_core crate
- 角色移动
- 敌人追踪
- 武器自动释放
- 碰撞与伤害
- XP 和升级
- 波次
- 10 分钟结算

验收：

- cargo test 通过
- headless simulate 可以跑 600 秒
- 输出 metrics
- 固定 seed 可复现

## Phase 2：Bevy Runtime 可玩版

目标：

- 把 GameCore 可视化。
- 做到本地可玩。

内容：

- 窗口
- 摄像机
- 玩家输入
- 基础 sprite 或形状
- HUD
- 升级界面
- 结算界面
- 简单音效

验收：

- 人工能完整玩一局
- runtime 与 headless 使用同一核心逻辑
- 画面能清楚表达怪潮和升级

## Phase 3：规则 Bot 与 Harness

目标：

- 不依赖人工跑大量局。

内容：

- IdleBot
- RandomBot
- CowardBot
- GreedyXpBot
- KiteBot
- TankBot
- BossHunterBot
- RouteBot
- 批量模拟命令
- 报告生成

验收：

- 一条命令跑多 Bot 多 seed
- 输出 summary.md 和 metrics.json
- 能拒绝明显坏内容

## Phase 4：内容配置化与首批内容

目标：

- 建立正式内容格式。

内容：

- 5 个角色
- 12 个武器
- 12 个被动
- 8 个进化
- 12 个敌人
- 3 个 Boss
- 1 张完整地图
- 10 分钟标准波次

验收：

- 内容 schema 通过
- Bot 门禁通过
- 人工试玩可接受

当前仓库提供 `tools/validate_phase4_roster_targets.py` 将本阶段名录目标转为纯 Python 预检：检查 docs/04 首批角色、武器、被动、进化、敌人、Boss、地图和标准波次 id 是否存在，并核对 Phase 4 数量目标。该预检只证明名录覆盖和轻量引用，不替代正式 Harness schema、静态预算、Bot 仿真、Replay 回归或人工试玩。

## Phase 5：AI 内容生成闭环

目标：

- 让 AI 生成候选内容，并由 Harness 筛选。

内容：

- generated_candidates
- validated_candidates
- accepted_content
- rejected_content
- repair_queue
- 自动报告
- AI 修正 prompt 模板

验收：

- AI 生成一批内容
- Harness 自动拒绝坏内容
- 至少有部分内容进入人工试玩候选

## Phase 6：AI Bot 训练

目标：

- 接入 Python Gymnasium/SB3。

内容：

- Gym 环境
- DQN 基线
- PPO 基线
- reward 配置
- 模型评估脚本
- RL Bot 加入 Harness

验收：

- RL Bot 学会基础生存
- RL Bot 超过 RandomBot
- RL Bot 能发现至少一种规则 Bot 未发现的问题

## Phase 7：美术与音频垂直切片

目标：

- 形成对外可展示风格。

内容：

- 主角 sprite
- 6 个敌人 sprite
- 3 个武器特效
- 1 个 Boss
- HUD 风格
- 升级卡牌
- 1 首 BGM
- 基础音效

验收：

- 可以录制 30-60 秒宣传片段
- 画面可爱且战斗信息清晰

## Phase 8：公开 Demo

目标：

- 可给外部玩家试玩。

内容：

- 1 张地图
- 3 个角色
- 16 个武器/被动
- 3 个 Boss
- 10 分钟标准局
- 本地设置
- 基础存档
- 图鉴
- Bug 收集方式

验收：

- 公开 Demo 可稳定运行
- 收集玩家反馈
- 收集 replay/遥测，若启用

## Phase 9：上线前扩展

目标：

- 从 Demo 变成可售卖版本。

内容：

- 3-5 张地图
- 8-12 个角色
- 40+ 武器/被动
- 20+ 进化
- 30+ 敌人
- 10+ Boss
- Meta 解锁
- 成就
- 设置
- 手柄支持
- Steam 页面素材

验收：

- Release Candidate 全量门禁通过
- 人工试玩确认首小时体验
- 性能达标

发布包进入 Phase 9 验收前，必须额外通过发布包清单校验：

```bash
python3 tools/validate_release_package_manifest.py harness/release/<package_manifest>.json --repo-root .
```

该清单要求记录 Runtime 包、发布压缩包、校验和、发布说明、内容 lockfile、素材 manifest 和最终 smoke 证据；它只能证明包证据完整，不能替代 Release Candidate 全部门禁。

## Phase 10：上线后运营

目标：

- 用 AI + Harness 支持长期内容更新。

内容：

- 每周候选内容批次
- 每月内容更新包
- 玩家行为反馈
- 新地图/新 Boss
- 节日糖果事件

验收：

- 更新不破坏旧内容
- Harness 报告稳定
- 玩家反馈可进入 AI 生成输入

## 阶段审计

当前仓库提供路线图阶段审计清单：

```text
harness/roadmap_audit/roadmap_phase_audit.json
```

该清单逐项记录 Phase 0 到 Phase 10 的：

- 当前状态：`complete`、`partial`、`blocked` 或 `pending`
- 阶段目标
- 验收项
- 当前证据路径
- 剩余 gap
- blocker
- 下一步行动

校验命令：

```bash
python3 tools/validate_roadmap_phase_audit.py \
  harness/roadmap_audit/roadmap_phase_audit.json \
  --repo-root . \
  --report harness/reports/2026-05-26_roadmap_phase_audit_001/roadmap_phase_audit.json \
  --markdown harness/reports/2026-05-26_roadmap_phase_audit_001/summary.md \
  --allow-incomplete
```

当前报告结论为 `roadmap_phase_audit_incomplete`：Phase 0 完成，Phase 1-8 多数受本机二进制启动、人工试玩、素材审查或 RL 泛化问题阻塞，Phase 9-10 仍处于 pending。该报告用于防止路线图状态被口头乐观化，不代表阶段已经完成。
