# AI 内容生成流水线

## 目标

让 AI 能持续生成《软糖风暴》的新内容，但不直接污染正式游戏。

内容类型：

- 武器
- 被动
- 进化组合
- 敌人
- Boss
- 波次
- 地图事件
- 角色
- 图鉴文本
- 剧情片段
- 美术提示词
- 音效提示词

## 内容池分层

```text
generated_candidates/
  AI 刚生成，未经验证

validated_candidates/
  schema 和静态预算通过

simulated_candidates/
  Bot 仿真通过

playtest_candidates/
  推荐人工试玩

accepted_content/
  正式进入游戏

rejected_content/
  拒绝但保留原因

repair_queue/
  值得修正的失败内容
```

## 生成输入

AI 生成内容前需要读取：

- 当前内容库
- 当前缺口
- 风格指南
- 数值预算
- 失败案例
- 目标流派
- 本批生成目标

例子：

```text
生成 10 个中期武器，要求：
- 其中 3 个是控制型
- 2 个是 Boss 单体型
- 2 个是召唤型
- 不允许与现有武器主题重复
- 输出 JSON
- 每个武器必须有美术描述和音效描述
```

## 静态校验

AI 内容必须先过静态校验：

- JSON 可解析
- id kebab-case
- id 唯一
- 引用存在
- 数值范围合法
- 标签合法
- 稀有度合法
- 文案非空
- 美术描述非空
- 不含明显违和词

## 理论预算

### 武器预算

计算：

- 理论 DPS
- 单体 DPS
- 群体 DPS
- 覆盖面积
- 冷却节奏
- 性能风险

判断：

- 是否过强
- 是否过弱
- 是否与同类武器重复
- 是否缺少反制或限制

### 敌人预算

计算：

- 有效生命 EHP
- 接触伤害压力
- 追击能力
- 数量压力
- 特殊能力复杂度

### 波次预算

计算：

- 每分钟生成生命总量
- 每分钟潜在接触伤害
- 敌人类型混合压力
- 同屏数量上限

## 仿真筛选

每批内容进入模拟：

1. 只加入一个新内容，测试单点影响。
2. 加入多个同批内容，测试组合影响。
3. 与已有强 Build 组合测试。
4. 与弱 Build 组合测试。
5. 多 seed 跑规则 Bot。
6. 高风险内容跑 RL Bot。

## 拒绝原因分类

- schema_error
- reference_error
- duplicate_theme
- too_strong
- too_weak
- performance_risk
- unclear_counterplay
- unreadable_visual
- lore_mismatch
- bot_exploit
- replay_regression

## 自动修正

AI 修正输入：

- 原内容
- 拒绝原因
- 指标
- 目标区间
- 相似合格内容

例子：

```text
焦糖风暴炮被拒绝：
- 理论群体 DPS 是同级武器 2.4 倍
- GreedyXpBot 胜率从 42% 提升到 91%
- 最大同屏区域特效造成性能风险
请保留主题，降低清群强度，增加冷却或缩小范围。
```

## 人工挑选

Harness 通过不代表直接上线。人工需要看：

- 名字是否好记
- 主题是否有趣
- 视觉是否可爱
- 是否能形成新流派
- 是否和已有内容差异明显
- 是否玩起来爽

人工审查记录必须能被 `harness/playtest/validate_manual_review.py --strict-acceptance` 校验通过，才能作为 `playtest_candidates -> accepted_content` 的证据。该校验只证明字段和 9 局证据完整，不证明内容已经好玩；如果人工评分低于目标或发现明确问题，仍应进入 `repair_queue` 或记录 failure case。

## 内容版本

每个正式内容记录：

- 进入版本
- 来源批次
- 通过报告
- 调整历史
- 人工备注

## AI 生成的边界

允许 AI 生成：

- 配置
- 文案
- 美术提示词
- 音效提示词
- 测试用例建议
- 平衡修改建议

谨慎让 AI 生成：

- 核心 ECS 系统
- 碰撞规则
- 存档格式
- 训练奖励函数

禁止 AI 直接绕过：

- 内容门禁
- 编译测试
- 仿真报告
- 人工最终审查
