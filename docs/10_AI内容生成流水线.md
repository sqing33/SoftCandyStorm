# AI 内容生成流水线

## 目标

让 AI 能持续生成《软糖风暴》的新内容，但不直接污染正式游戏。

内容类型：

- 武器
- 被动
- 进化组合
- 敌人
- Boss
- 波次
- 地图事件
- 角色
- 图鉴文本
- 剧情片段
- 美术提示词
- 音效提示词

## 内容池分层

```text
generated_candidates/
  AI 刚生成，未经验证

validated_candidates/
  schema 和静态预算通过

simulated_candidates/
  Bot 仿真通过

playtest_candidates/
  推荐人工试玩

accepted_content/
  正式进入游戏

rejected_content/
  拒绝但保留原因

repair_queue/
  值得修正的失败内容
```

如果一次 AI 生成只覆盖局部内容，例如只新增几个被动或敌人，先放入：

```text
generated_candidate_patches/
  局部候选补丁，不能直接交给正式 GameCore 加载
```

再通过 `tools/materialize_content_candidate_pack.py` 叠加到基础内容包，生成完整 `generated_candidates/<batch>/`，并用 `tools/validate_materialized_content_pack.py` 做候选标记、内容计数和引用关系预检后，进入正式 Harness 候选流水线。

## 生成输入

AI 生成内容前需要读取：

- 当前内容库
- 当前缺口
- 风格指南
- 数值预算
- 失败案例
- 目标流派
- 本批生成目标

例子：

```text
生成 10 个中期武器，要求：
- 其中 3 个是控制型
- 2 个是 Boss 单体型
- 2 个是召唤型
- 不允许与现有武器主题重复
- 输出 JSON
- 每个武器必须有美术描述和音效描述
```

## 静态校验

AI 内容必须先过静态校验：

- JSON 可解析
- id kebab-case
- id 唯一
- 引用存在
- 数值范围合法
- 标签合法
- 稀有度合法
- 文案非空
- 美术描述非空
- 不含明显违和词

当前仓库提供三层候选校验：

- `tools/validate_content_candidates.py`：纯 Python 轻量校验，用于检查 `generated_candidate_patches` 中尚未合并为完整内容包的局部候选，覆盖通用字段、被动/敌人字段、重复 id 和候选池红线。
- `tools/materialize_content_candidate_pack.py`：把局部候选叠加到基础内容包，生成完整的 `generated_candidates/<batch>` 内容包候选。
- `tools/validate_materialized_content_pack.py`：纯 Python 完整候选包预检，检查候选池标记、物化来源、目录计数、角色初始 loadout、进化条件、波次地图/敌人/Boss 引用。
- `harness/content_review/create_content_candidate_design_review_draft.py`、`harness/content_review/create_content_candidate_review_packet.py` 与 `harness/content_review/validate_content_candidate_design_review.py`：为完整候选包中新增内容生成设计审查草稿和真人审查包，并校验真人是否逐项审查主题、差异、流派潜力、反制可读性、美术 / 音效适配和风险。
- `game_harness validate-candidates`：正式 Harness 校验，用于完整内容包，包含 GameCore Schema、引用关系和静态预算门禁。

纯 Python 校验、物化和预检只允许候选继续留在生成候选层，不能把内容推进到 `validated_candidates`。

## 理论预算

### 武器预算

计算：

- 理论 DPS
- 单体 DPS
- 群体 DPS
- 覆盖面积
- 冷却节奏
- 性能风险

判断：

- 是否过强
- 是否过弱
- 是否与同类武器重复
- 是否缺少反制或限制

### 敌人预算

计算：

- 有效生命 EHP
- 接触伤害压力
- 追击能力
- 数量压力
- 特殊能力复杂度

### 波次预算

计算：

- 每分钟生成生命总量
- 每分钟潜在接触伤害
- 敌人类型混合压力
- 同屏数量上限

## 仿真筛选

每批内容进入模拟：

1. 只加入一个新内容，测试单点影响。
2. 加入多个同批内容，测试组合影响。
3. 与已有强 Build 组合测试。
4. 与弱 Build 组合测试。
5. 多 seed 跑规则 Bot。
6. 高风险内容跑 RL Bot。

## 拒绝原因分类

- schema_error
- reference_error
- duplicate_theme
- too_strong
- too_weak
- performance_risk
- unclear_counterplay
- unreadable_visual
- lore_mismatch
- bot_exploit
- replay_regression

## 自动修正

AI 修正输入：

- 原内容
- 拒绝原因
- 指标
- 目标区间
- 相似合格内容

例子：

```text
焦糖风暴炮被拒绝：
- 理论群体 DPS 是同级武器 2.4 倍
- GreedyXpBot 胜率从 42% 提升到 91%
- 最大同屏区域特效造成性能风险
请保留主题，降低清群强度，增加冷却或缩小范围。
```

## 人工挑选

Harness 通过不代表直接上线。人工需要看：

- 名字是否好记
- 主题是否有趣
- 视觉是否可爱
- 是否能形成新流派
- 是否和已有内容差异明显
- 是否玩起来爽

人工审查记录必须能被 `harness/playtest/validate_manual_review.py --strict-acceptance` 校验通过，才能作为 `playtest_candidates -> accepted_content` 的证据。该校验只证明字段和 9 局证据完整，不证明内容已经好玩；如果人工评分低于目标或发现明确问题，仍应进入 `repair_queue` 或记录 failure case。

在候选进入仿真或人工试玩前，还应先完成设计审查：

```bash
python3 harness/content_review/create_content_candidate_design_review_draft.py \
  harness/generated_candidates/<full-pack> \
  --repo-root . \
  --preflight-report harness/reports/<preflight-report>/summary.md \
  --out harness/content_review/drafts/<full-pack>_design_review_draft.json

python3 harness/content_review/create_content_candidate_review_packet.py \
  harness/generated_candidates/<full-pack> \
  --repo-root . \
  --preflight-report harness/reports/<preflight-report>/summary.md \
  --review-draft harness/content_review/drafts/<full-pack>_design_review_draft.json \
  --out harness/reports/<content-review-packet>/summary.md

python3 harness/content_review/validate_content_candidate_design_review.py \
  harness/content_review/reviews/<review>.json \
  --repo-root . \
  --report harness/reports/<content-design-review>/content_design_review.json \
  --markdown harness/reports/<content-design-review>/summary.md
```

设计审查只允许把候选标为 `simulate_candidate`、`repair`、`reject` 或 `needs_more_review`。它不能写入 `accepted_content`，也不能替代静态预算、Bot 仿真、Replay 回归或 9 局人工试玩验收。若需要把 `simulate_candidate` 审查结果落成可审计 staging，应使用 `harness/content_review/promote_content_simulation_candidate.py` 和 `harness/content_review/validate_content_simulation_candidate_manifest.py`；该 staging 仍不得写入 `validated_candidates`、`simulated_candidates`、`playtest_candidates` 或 `accepted_content`。

在填写正式内容锁或声称候选可接受前，还应生成最终接受证据包：

```bash
python3 harness/content_review/create_content_acceptance_review_packet.py \
  harness/generated_candidates/<full-pack> \
  --repo-root . \
  --report harness/reports/<content-acceptance-packet>/content_acceptance_review_packet.json \
  --markdown harness/reports/<content-acceptance-packet>/summary.md
```

该证据包会检查候选预检、静态预算、设计审查、人工试玩、Demo readiness 和 accepted content lockfile 等证据是否齐全。它只汇总证据缺口，不接受内容、不运行仿真、不复制候选，也不允许绕过 `generated_candidates -> validated_candidates -> simulated_candidates -> playtest_candidates -> accepted_content`。

最终接受记录和 manifest 还需要独立校验：

```bash
python3 harness/content_review/validate_content_final_acceptance.py \
  harness/content_review/final_acceptance/<review>.json \
  --repo-root . \
  --report harness/reports/<content-final-acceptance>/content_final_acceptance.json \
  --markdown harness/reports/<content-final-acceptance>/summary.md

python3 harness/content_review/validate_content_acceptance_manifest.py \
  harness/content_review/accepted/<full-pack>/acceptance_manifest.json \
  --repo-root . \
  --report harness/reports/<content-acceptance-manifest>/content_acceptance_manifest.json \
  --markdown harness/reports/<content-acceptance-manifest>/summary.md
```

Final acceptance 记录必须绑定有效 `content_simulation_candidate_manifest_valid` 和 `accepted_content_lockfile_valid` 报告；acceptance manifest 再绑定该 final acceptance、simulation candidate manifest 和 lockfile，并校验 accepted contents 的 id、type、path 与 source simulation candidate 对齐。二者都不能声明 Runtime 集成或 release ready。

- 进入版本
- 来源批次
- 通过报告
- 调整历史
- 人工备注

## AI 生成的边界

允许 AI 生成：

- 配置
- 文案
- 美术提示词
- 音效提示词
- 测试用例建议
- 平衡修改建议

谨慎让 AI 生成：

- 核心 ECS 系统
- 碰撞规则
- 存档格式
- 训练奖励函数

禁止 AI 直接绕过：

- 内容门禁
- 编译测试
- 仿真报告
- 人工最终审查
